## UITrace Desktop 界面原型文档 (Wireframe)

本原型文档采用线框图形式，描绘了 UITrace Desktop 应用的关键界面布局和组件，旨在提供清晰的用户交互蓝图。

### 1\. 总体布局结构 (Global Layout)

UITrace Desktop 采用标准的现代桌面应用布局，左侧为导航，右侧为主要工作区。

```
+-------------------------------------------------------------+
| [Tauri App Bar]                                             |
|-------------------------------------------------------------|
| [侧边栏]        | [头部控制栏]                                |
| (主导航)        | (脚本/模块名称 | 运行/录制按钮 | 设置)       |
|-----------------|---------------------------------------------|
|                 | [主工作区]                                  |
|                 | (根据当前选择的界面进行内容切换)            |
|                 |                                             |
+-------------------------------------------------------------+
```

-----

### 2\. 界面原型 A：项目主界面与脚本管理 (Dashboard & Script Management)

**目的:** 概览项目结构，快速启动脚本或录制新用例。

```
+-------------------------------------------------------------+
| [侧边栏]        | 脚本名称: 项目概览 | [连接状态: Server OK] | [用户: tester_user] |
|-----------------|---------------------------------------------|
| 📂 项目导航     | ## 模块与脚本列表                             |
| * 🏠 概览       | +-----------------------------------------+ |
| * ⚙️ 设置       | | 模块/用例           | 最后修改人 | 状态 | |
| * ☁️ Server同步 | |---------------------|----------|------|
|-----------------| | 📂 登录模块 (5)     |          |      |
| 📂 **模块 A** | | * 🟢 TC001-成功登录 | 张三     | PASS |
|   * 脚本 1      | | * 🔴 TC002-密码错误 | 李四     | FAIL |
|   * 脚本 2      | | 📂 购物车模块 (12)  |          |      |
| 📂 **模块 B** | | * 🟡 TC010-数据驱动 | 王五     | SKIP |
|                 | +-----------------------------------------+ |
|                 |                                             |
|                 | [底部区域: 全局运行结果统计 (最近 7 天 Pass/Fail)] |
+-------------------------------------------------------------+
```

#### 关键组件：

  * **项目导航树 (Sidebar):** 左侧树状结构，同步 Server 端的模块和脚本结构。
  * **快速操作区:** 列表上方，提供 **[+ 新建脚本]**、**[☁️ 从 Server 同步]**、**[▶️ 批量运行]** 按钮。
  * **状态图标:** 清晰显示各脚本的最新执行状态（🟢 成功, 🔴 失败, 🟡 跳过）。

### 3\. 界面原型 B：脚本编辑与录制界面 (Script Editor & Recorder View)

**目的:** 编写、修改、调试脚本步骤，并配置数据驱动和容错性。

#### 布局：三栏编辑模式

```
+-------------------------------------------------------------+
| [头部控制栏] 脚本名称: TC001-成功登录 | [数据驱动: login_data.csv] | [▶️ 运行] [⏺️ 启动录制] [💾 保存] |
|-------------------------------------------------------------|
| [左侧: 步骤列表] | [中间: 步骤详情/定位符] | [右侧: 浏览器预览 (可选)] |
| 1. 🌐 Navigate | 步骤名称: 输入用户名                             | (Tauri Webview)       |
| 2. ⌨️ Type (User) | 动作类型: **Type (输入)** | +-------------------+ |
| 3. 🖱️ Click (Login) | 输入值: **${Username}** (从数据表获取)           | | [浏览器实时截图]  |
| 4. ✅ Assert Text | 超时 (秒): **15** (用于容错)                     | | [高亮显示当前元素] |
| 5. 📸 Screenshot |                                                 | +-------------------+ |
|-----------------| **定位符与容错配置** |                       |
| [JSON代码切换] | +-----------------------------------------+ |                       |
|                 | | **优先级** | **类型** | **值** | |                       |
|                 | | 1 (首选) | ID     | `username-field-v3` | |                       |
|                 | | 2 (备选) | CSS    | `input[name='user']`| |                       |
|                 | | 3 (备选) | XPath  | `//form//input[1]`  | |                       |
|                 | +-----------------------------------------+ |                       |
+-------------------------------------------------------------+
```

#### 关键组件：

  * **步骤列表 (左侧):** 显示脚本中的所有步骤，支持拖拽排序、快捷添加/删除。
  * **数据绑定指示:** 在输入值字段直接显示 `${Placeholder}` 占位符，方便用户理解数据驱动。
  * **容错编辑器 (中间):** 核心界面。清晰展示多重定位符的优先级，并允许用户手动修改或添加新的定位符，这是 **UITrace** 区别于其他工具的关键。
  * **录制启动:** **[⏺️ 启动录制]** 按钮启动浏览器会话，并在左侧实时添加新步骤。

### 4\. 界面原型 C：测试结果与视觉对比 (Result & Visual Comparison View)

**目的:** 详细审查失败用例的原因，特别是视觉回归的差异。

#### 布局：日志/摘要 + 视觉对比分离

```
+-------------------------------------------------------------+
| [头部控制栏] 测试结果: TC002-密码错误 (失败) | 运行时间: 12.4s | [重新运行] [⬆️ 上传报告] |
|-------------------------------------------------------------|
| ## 运行摘要与日志                                             |
| +---------------------------------------------------------+ |
| | 状态: 🔴 FAIL | 失败步骤: 3. Click (Login)             | |
| | 错误信息: 元素 'submit-login-v2' 在 15s 内不可交互或定位符失效 | |
| |---------------------------------------------------------| |
| | 详细日志输出 (Log Viewer)                               | |
| | 10:00:01 INFO: 开始执行用例 TC002...                     | |
| | 10:00:05 DEBUG: 尝试定位 ID=submit-login-v2... (失败)    | |
| | 10:00:10 DEBUG: 尝试备选 CSS=button.primary-btn... (失败) | |
| | 10:00:15 ERROR: 步骤超时，报告失败。                      | |
| +---------------------------------------------------------+ |
|                                                             |
| ## 视觉回归对比 (Visual Regression)                           |
| +---------------------------------------------------------+ |
| | [基准截图 (Baseline)]       | [当前截图 (Actual)]       | |
| | (上次成功运行保存的截图)    | (本次失败运行捕获的截图)    | |
| |-----------------------------|-----------------------------| |
| | [切换: 并排/叠加/差异图] | 视觉差异度: **12.5% (失败)** | |
| | [可调节容忍度滑块] | [✅ 接受为新的基准] (上传至 Server) | |
| +---------------------------------------------------------+ |
+-------------------------------------------------------------+
```

#### 关键组件：

  * **摘要区:** 突出显示失败步骤和错误原因，方便快速诊断是定位符问题还是断言失败。
  * **日志 Viewer:** 详细展示回放引擎的日志，特别是 **容错尝试** 的过程（例如，明确显示尝试了 ID、然后是 CSS，最终都失败的记录）。
  * **视觉对比区:**
      * 提供 **并排 (Side-by-Side)**、**叠加 (Overlay)**、**差异图 (Diff Map)** 三种视图模式。
      * **容忍度滑块:** 允许测试人员在结果页调整可接受的像素差异百分比，用于微调报告精度。
      * **[✅ 接受为新的基准]** 按钮：一键将当前截图上传到 Server 端，替换旧的 Baseline，完成视觉回归测试的确认流程。
